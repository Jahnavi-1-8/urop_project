1. PROJECT OVERVIEW & EXECUTIVE SUMMARY
====================================================================================================
The goal of this project is to build an automated, interpretable, and reproducible machine learning
system that classifies digital photographs of apple leaves into four distinct health categories:
  1. Apple Scab (Fungal infection)
  2. Black Rot (Fungal infection)
  3. Cedar Apple Rust (Fungal infection)
  4. Healthy (Asymptomatic tissue)

Rather than treating the machine learning model as an opaque "black-box" (as is often the case with
deep neural networks), this project follows an established classical computer vision methodology:
we isolate leaf tissue using color segmentation in the HSV color space, compute handcrafted
descriptors capturing shape, texture, and color distributions (totaling 532 features), and evaluate
two classic machine learning classifiers:
  - Random Forest Classifier (Ensemble Bagging)
  - Support Vector Machine (SVM with RBF Kernel and probability calibration)

Results from our test set (635 held-out samples, 20% stratified split):
  - Random Forest achieved an overall accuracy of 96.22% (Macro F1: 0.9605).
  - SVM achieved an overall accuracy of 95.12% (Macro F1: 0.9451).
  - Feature extraction across all 3,171 images takes under 50 seconds.
  - The trained models are deployed via an interactive Streamlit web dashboard.

2. PROBLEM STATEMENT & BOTANICAL CONTEXT
====================================================================================================
Apple orchards (*Malus domestica*) suffer billions of dollars in annual losses worldwide due to
foliar fungal diseases. When leaves are infected:
  - Photosynthetic surface area decreases.
  - Premature leaf drop (defoliation) weakens the tree.
  - Fruit yield and quality drop drastically.

The four conditions addressed in Phase 1 are:

1. APPLE SCAB (Venturia inaequalis):
   - Symptoms: Olive-green to dull dark brown velvety or corky lesions, often with irregular borders.
   - Impact: If uncontrolled, lesions spread to fruit, causing cracking, scabbing, and rot.

2. BLACK ROT (Diplocarpa mali / Botryosphaeria obtusa):
   - Symptoms: Concentric circular "frog-eye" leaf spots with tan/brown centers and dark purple halos.
   - Impact: Causes severe fruit mummification and canker formation on tree limbs.

3. CEDAR APPLE RUST (Gymnosporangium juniperi-virginianae):
   - Symptoms: Bright yellow-orange pustules on the upper leaf surface, later developing tiny raised
     fruiting bodies and tube-like spore structures on the lower surface.
   - Impact: Requires both eastern red cedar and apple trees to complete its life cycle. Leads to
     premature defoliation.

4. HEALTHY:
   - Clear, uniform green leaf blade with intact cuticle and veins, free of necrotic lesions.

Manual visual inspection by agronomists is subjective, labor-intensive, and impossible to scale
continuously across vast acreage. An automated vision-based classifier provides objective, rapid,
and consistent diagnosis.

4. DATASET DETAILS, CLASS DISTRIBUTION & SPLITTING STRATEGY
====================================================================================================
The project uses the authentic PlantVillage Apple Leaf dataset subset:

Total Dataset: 3,171 images
  - Apple___Apple_scab       : 630 images  (19.87%)
  - Apple___Black_rot        : 621 images  (19.58%)
  - Apple___Cedar_apple_rust : 275 images  ( 8.67%)
  - Apple___healthy          : 1,645 images (51.88%)

NOTICE THE CLASS IMBALANCE:
Healthy leaves make up more than half the dataset (51.88%), while Cedar Apple Rust represents only
8.67%. If an algorithm simply predicted "Healthy" every time, it would achieve ~52% accuracy while
being completely useless. This makes Macro-averaged metrics and confusion matrix inspection essential.

SPLITTING METHODOLOGY:
To evaluate generalization on unseen data, the dataset is partitioned using an 80/20 Stratified Split:
  - Total Training Samples : 2,536 (80%)
  - Total Test Samples     :   635 (20%)

What is Stratification and Why Is It Necessary?
Random splitting might accidentally place too few minority samples (Cedar Apple Rust) into the test
set. Stratification guarantees that the 80/20 proportion is maintained identically across every
individual class:
  - Apple Scab       : 504 train | 126 test
  - Black Rot        : 497 train | 124 test
  - Cedar Apple Rust : 220 train |  55 test
  - Healthy          : 1,315 train | 330 test

Reproducibility:
The split uses a fixed random seed (`random_state=42`), ensuring that all models are trained and
evaluated on the exact same data partitions every time.

5. IMAGE PREPROCESSING PIPELINE (WHAT IT DOES & WHY)
====================================================================================================
Located in `src/preprocessing.py`.

A major challenge in leaf classification is that raw camera images contain varying resolutions,
lighting differences, and background noise (shadows, mounting clips, bench surfaces).
Our preprocessing pipeline follows five deliberate steps:

STEP 1: IMAGE INGESTION & ROBUST ERROR HANDLING
  - Images are read via `cv2.imread`.
  - Corrupt files, empty arrays, or non-image files are caught gracefully and return `None` rather
    than crashing the pipeline.

STEP 2: STANDARDIZED RESIZING (500 x 500)
  - Images from cameras have different aspect ratios and resolutions.
  - Resizing to a uniform (500, 500) grid standardizes the pixel coordinate space while preserving
    fine texture details needed for Haralick GLCM computation.

STEP 3: COLOR SPACE CONVERSION (BGR -> RGB -> HSV)
  - OpenCV loads images in BGR format. We convert to RGB for proper human viewing and standard
    color science.
  - Next, we convert RGB to HSV (Hue, Saturation, Value):
    * Hue (0-179 in OpenCV): Represents the dominant color wavelength (color family).
    * Saturation (0-255): Represents the purity or vividness of the color.
    * Value (0-255): Represents the brightness or luminance.
  - WHY HSV INSTEAD OF RGB?
    In RGB, a shadow changes all three channels (R, G, B) simultaneously, making thresholding
    fragile. In HSV, shadows primarily affect the "Value" channel, while "Hue" remains constant.
    This allows us to identify green foliage and brown disease lesions regardless of ambient light.

STEP 4: DUAL-MASK COLOR SEGMENTATION (LEAF ISOLATION)
  - We create two HSV color masks:
    1. Healthy Foliage Mask (Green Spectrum):
       Lower Bound: [H=25, S=0, V=20]
       Upper Bound: [H=100, S=255, V=255]
       This captures normal leaf chlorophyll across light and dark shades.
    2. Diseased Lesion Mask (Brown / Rust Spectrum):
       Lower Bound: [H=10, S=0, V=10]
       Upper Bound: [H=30, S=255, V=255]
       This captures the necrotic, brown, yellow, and rust hues of scab, rot, and rust lesions.
    3. Composite Bitwise OR:
       Final_Mask = bitwise_or(Healthy_Mask, Disease_Mask)
       (Using bitwise OR prevents byte overflow that happens with simple '+' addition in NumPy).
    4. Bitwise AND Masking:
       Segmented_Leaf = bitwise_and(RGB_Image, RGB_Image, mask=Final_Mask)
  - WHAT DOES THIS ACCOMPLISH?
    All background pixels (bench, shadow, white card) are set to pure black [0, 0, 0], while all
    healthy and diseased leaf pixels are preserved.

STEP 5: GRAYSCALE EXTRACTION
  - The segmented RGB leaf is converted to grayscale (`cv2.cvtColor(..., cv2.COLOR_RGB2GRAY)`).
  - This single-channel intensity image is passed to the shape and texture descriptor algorithms.

6. FEATURE EXTRACTION DEEP DIVE (THE 532-DIMENSIONAL VECTOR)
====================================================================================================
Located in `src/feature_extraction.py`.

Instead of feeding raw pixels (which would be 500 x 500 x 3 = 750,000 dimensions—far too large for
classical ML models without overfitting), we extract 532 engineered features combining:
  1. Shape (7 features)
  2. Texture (13 features)
  3. Color (512 features)

Total Feature Dimension = 512 + 13 + 7 = 532 features.
Our implementation calculates this dimension dynamically and verifies it during execution.

----------------------------------------------------------------------------------------------------
6.1 HU MOMENTS (SHAPE DESCRIPTORS — 7 DIMENSIONS)
----------------------------------------------------------------------------------------------------
- WHAT THEY ARE:
  Derived from normalized central spatial moments of the grayscale segmented leaf.
  Calculated using `cv2.moments(gray)` followed by `cv2.HuMoments(moments).flatten()`.
- WHY THEY ARE USEFUL:
  Ming-Kuei Hu (1962) proved that these 7 nonlinear moment combinations are invariant to:
    1. Translation (shifting leaf position)
    2. Scale (zooming in or out)
    3. Rotation (leaf angle on the surface)
- WHAT THEY CAPTURE:
  They quantify the global geometry and boundary irregularities of the leaf blade and major lesion
  groupings. For example, severe disease can deform leaf margins or create large irregular necrotic
  clusters that shift the higher-order spatial moments.

----------------------------------------------------------------------------------------------------
6.2 HARALICK TEXTURE FEATURES (GLCM — 13 DIMENSIONS)
----------------------------------------------------------------------------------------------------
- WHAT THEY ARE:
  Robert Haralick (1973) proposed texture analysis based on Gray-Level Co-occurrence Matrices (GLCM).
  A GLCM tabulates how often pairs of pixel intensities occur at specified spatial offsets (e.g., 1
  pixel distance) and angles.
- COMPUTATION:
  Using `mahotas.features.haralick(gray).mean(axis=0)`, we compute the GLCM across four directions:
    - 0 degrees   (horizontal)
    - 45 degrees  (diagonal right)
    - 90 degrees  (vertical)
    - 135 degrees (diagonal left)
  Averaging across the four directions produces a rotation-invariant 13-element feature vector:
    1. Angular Second Moment (ASM / Uniformity / Energy): High when image texture is very uniform.
    2. Contrast: Measures intensity variation between neighboring pixels. High in diseased leaves
       with sharp necrotic borders.
    3. Correlation: Linear dependency of gray levels of neighbor pixels.
    4. Variance: Measures the dispersion of pixel intensity values.
    5. Inverse Difference Moment (IDM / Homogeneity): Measures smoothness of local textures.
    6. Sum Average
    7. Sum Variance
    8. Sum Entropy
    9. Entropy: Measures texture randomness or complexity. Diseased leaves with mottled lesions have
       significantly higher entropy than smooth, healthy leaf blades.
    10. Difference Variance
    11. Difference Entropy
    12. Information Measure of Correlation 1
    13. Information Measure of Correlation 2

----------------------------------------------------------------------------------------------------
6.3 3D HSV COLOR HISTOGRAM (COLOR DISTRIBUTION — 512 DIMENSIONS)
----------------------------------------------------------------------------------------------------
- WHAT IT IS:
  A 3D joint frequency distribution across Hue, Saturation, and Value channels.
- COMPUTATION:
  Using `cv2.calcHist([hsv_segmented], [0, 1, 2], None, [8, 8, 8], [0, 256, 0, 256, 0, 256])`.
  - We divide Hue into 8 bins.
  - We divide Saturation into 8 bins.
  - We divide Value into 8 bins.
  - Total bins = 8 x 8 x 8 = 512 bins.
  - Flattened into a 512-dimensional vector.
- NORMALIZATION:
  The histogram is normalized using L2 norm (`cv2.normalize(hist, hist)`).
  WHY NORMALIZE?
  A larger leaf has more pixels than a smaller leaf. Normalization makes the histogram independent
  of leaf surface area, representing the PROPORTION of color states rather than raw pixel counts.
- WHAT IT CAPTURES:
  This is the most discriminative feature descriptor for distinguishing:
  - Vibrant green chlorophyll (Healthy)
  - Olive-brown velvety tones (Apple Scab)
  - Dark brown/black frog-eye patches (Black Rot)
  - Bright yellow-orange pustules (Cedar Apple Rust)

----------------------------------------------------------------------------------------------------
COMBINED FEATURE VECTOR ASSEMBLY
----------------------------------------------------------------------------------------------------
Order: [ 512 Color Histogram Features  |  13 Haralick Texture Features  |  7 Hu Moments ]
Total: 532 scalar features per image.

7. FEATURE SCALING & PREVENTING DATA LEAKAGE
====================================================================================================
Located in `src/train.py`.

WHAT IS DATA LEAKAGE AND WHY IS IT FATAL IN ML?
Data leakage occurs when information from outside the training dataset (specifically from the test
set) is used to create or tune the model. A common rookie mistake is:
  "scaler.fit_transform(all_3171_samples)"  <-- WRONG!
If you scale the entire dataset before splitting, the test set's mean, min, and max values leak into
the training feature distribution. The model gets an unfair peek at test data, yielding artificially
inflated test accuracy that collapses in real-world deployment.

OUR IMPLEMENTATION (STRICT ZERO LEAKAGE):
  1. The dataset is first split into X_train (2,536 samples) and X_test (635 samples).
  2. The `MinMaxScaler(feature_range=(0, 1))` is fitted SOLELY on X_train:
       scaler.fit(X_train)
  3. X_train is transformed:
       X_train_scaled = scaler.transform(X_train)
  4. X_test is transformed using the previously fitted scaler:
       X_test_scaled = scaler.transform(X_test)
  5. The fitted scaler is saved to `models/scaler.joblib` so that unseen inference images in
     `src/predict.py` and `app/app.py` use the exact same scaling parameters.

WHY DOES SVM REQUIRE FEATURE SCALING?
SVM computes geometric Euclidean distances between feature vectors ($||\mathbf{x}_i - \mathbf{x}_j||^2$)
to determine the optimal separating hyperplane. In our 532-D vector:
  - Normalized histogram values are in the range [0.0, 1.0].
  - Hu moments can be tiny fractions (e.g., $10^{-6}$).
  - Haralick variance or contrast values can be large numbers (e.g., $50.0$ to $500.0$).
Without scaling, Haralick contrast would dominate the Euclidean distance calculation, completely
blinding the SVM to color and shape! MinMaxScaler maps every single feature into [0, 1], giving equal
mathematical footing to all descriptors.

WHY DOES RANDOM FOREST WORK WELL EITHER WAY?
Random Forest splits nodes based on single feature threshold inequalities ($x_j \le \theta$).
Because rank order is preserved under any monotonic scaling, Random Forest is mathematically
invariant to feature scale. We use scaled data consistently across both models for architectural
uniformity.

====================================================================================================
8. WHY THESE TWO MODELS? (RANDOM FOREST VS. SVM)
====================================================================================================
Per the project guidelines, we explicitly compared exactly two classical supervised algorithms:
Random Forest and Support Vector Machine.

----------------------------------------------------------------------------------------------------
8.1 MODEL 1: RANDOM FOREST CLASSIFIER
----------------------------------------------------------------------------------------------------
- WHAT IT IS:
  An ensemble method combining multiple decision trees (we configure 100 estimators).
  Each tree is trained on a bootstrap sample of the training data (Bagging), and at each split,
  only a random subset of features is evaluated ($\sqrt{532} \approx 23$ features).
- WHY RANDOM FOREST FOR APPLE LEAVES?
  1. Non-linear Feature Interactions: Leaf diseases have conditional rules (e.g., IF hue is yellow-orange
     AND Haralick entropy is high, THEN Cedar Apple Rust). Decision trees naturally model such rules.
  2. High Dimensionality Robustness: With 532 features, individual features may have correlation;
     Random Forest randomly samples features per split, preventing dominant features from masking
     subtle textures.
  3. Inherent Resistance to Overfitting: Averaging predictions across 100 uncorrelated trees drastically
     reduces variance compared to a single decision tree.

----------------------------------------------------------------------------------------------------
8.2 MODEL 2: SUPPORT VECTOR MACHINE (SVM)
----------------------------------------------------------------------------------------------------
- WHAT IT IS:
  A maximum-margin classifier that constructs optimal hyperplanes in a high-dimensional feature space
  to separate data classes with the widest possible geometric margin.
- KERNEL SELECTION: RADIAL BASIS FUNCTION (RBF)
  Apple leaf feature space is not linearly separable. The RBF (Gaussian) kernel:
    $K(\mathbf{x}_i, \mathbf{x}_j) = \exp(-\gamma ||\mathbf{x}_i - \mathbf{x}_j||^2)$
  implicitly maps the 532-dimensional input vectors into an infinite-dimensional Hilbert space where
  curved decision surfaces become linearly separable.
- PROBABILITY ESTIMATION VIA PLATT SCALING:
  Standard SVM only produces signed geometric distances from the decision hyperplane. By setting
  `probability=True`, scikit-learn uses Platt Scaling (fitting an internal logistic sigmoid model via
  5-fold cross-validation) to convert raw distances into true, calibrated class probabilities
  between 0.0 and 1.0.

----------------------------------------------------------------------------------------------------
8.3 WHY OTHER MODELS WERE EXCLUDED
----------------------------------------------------------------------------------------------------
In the reference repository, up to 7 models were tried (Logistic Regression, LDA, KNN, Decision Trees,
Gaussian Naive Bayes, etc.). Per the project instructions, these were excluded because:
  - Linear Regression / LDA: Assume linear separability, which fails on complex multimodal color spaces.
  - Decision Trees (single): Prone to extreme overfitting and high variance.
  - KNN: High inference latency in 532 dimensions (Curse of Dimensionality; distance between all points
    becomes equidistant, degrading neighborhood quality).
  - Gaussian Naive Bayes: Assumes complete feature independence, which is completely false for color
    histogram bins and adjacent GLCM texture features.
Comparing Random Forest (Ensemble Trees) vs. SVM (Margin Hyperplane) represents the two most powerful,
fundamentally distinct paradigms in classical machine learning.

10.3 WHY ACCURACY ALONE IS INSUFFICIENT — IN-DEPTH ANALYSIS
----------------------------------------------------------------------------------------------------
In an academic project, one must never proclaim a model "the winner" based solely on an accuracy
number. Looking closely at the per-class metrics reveals crucial trade-offs:

1. THE CEDAR APPLE RUST DYNAMICS:
   - SVM achieved 100.0% Precision on Cedar Apple Rust: whenever SVM predicted Cedar Apple Rust,
     it was correct 100% of the time (zero false alarms).
   - However, SVM's Recall was only 89.09% (it missed 6 infected leaves, misclassifying them as scab
     or healthy). In agriculture, missing an active infection (False Negative) allows disease to
     spread uncontrollably.
   - Random Forest achieved 96.36% Recall on Cedar Apple Rust, catching almost all infections with
     only a negligible dip in precision (98.15%).

2. WHY RANDOM FOREST IS THE PREFERRED OPERATIONAL MODEL:
   - Random Forest achieved a higher Macro Recall (95.82% vs. 93.90%) and higher Macro F1 (96.05%
     vs. 94.51%).
   - Because Macro averages weight all 4 diseases equally (regardless of whether a class has 55
     or 330 samples), Random Forest demonstrates superior sensitivity and robustness across
     minority classes.

11. END-TO-END INFERENCE & PREDICTION PIPELINE (HOW IT WORKS IN CODE)
====================================================================================================
Located in `src/predict.py`.

When a user provides an unseen leaf photograph (e.g., via CLI or web UI), the `AppleLeafPredictor`
executes the complete sequence in ~20 milliseconds:

  Input Leaf Image (.JPG / .PNG / NumPy array)
                    │
                    ▼
     [1. Preprocessing & Resizing]
     - Resized to (500, 500)
     - Converted BGR -> RGB -> HSV
                    │
                    ▼
     [2. Dual-Mask HSV Segmentation]
     - Healthy mask (green) + Disease mask (brown/rust)
     - Bitwise AND eliminates background into black (0)
                    │
                    ▼
     [3. Multi-Modal Feature Extraction]
     - Hu Moments (7) from grayscale segmented leaf
     - Haralick Textures (13) from GLCM
     - HSV 3D Color Histogram (512) normalized
     - Concatenation -> 1D vector (532 features)
                    │
                    ▼
     [4. Feature Normalization]
     - Scaled using pre-fitted `scaler.joblib` (MinMaxScaler)
                    │
                    ▼
     [5. Model Inference]
     - Loaded model (Random Forest or SVM) computes `predict_proba()`
                    │
                    ▼
     [6. Diagnostic Synthesis]
     - Top class identified (ArgMax)
     - True confidence probability extracted (e.g., 96.00%)
     - Pathological explanation generated
     - Structured JSON / Dictionary returned

NO FAKE CONFIDENCE:
Both Random Forest (tree leaf voting fractions) and SVM (Platt scaling sigmoid calibration) output
genuine, mathematically valid probabilities that sum to 1.0 across the 4 classes.

14. PROJECT LIMITATIONS
====================================================================================================
To maintain academic honesty, the following constraints must be noted:

1. CONTROLLED ENVIRONMENT BIAS:
   The PlantVillage dataset was captured in laboratory conditions with leaves placed flat against
   uniform gray/white backdrops. In an actual outdoor orchard, leaves overlap with branches, sky,
   and soil, which will require adaptive semantic segmentation (e.g., U-Net or Mask R-CNN).

2. CLASS IMBALANCE:
   Cedar Apple Rust has only 275 images compared to 1,645 Healthy images. While Random Forest
   handled this well (96.36% recall), SVM's recall dropped to 89.09% on the minority class.

3. HANDCRAFTED FEATURE LIMITATIONS:
   The 532 handcrafted features rely on predefined color and texture mathematics. Unusual surface
   blemishes, dust, dry weather, or pesticide spray residue can mimic lesion patterns and cause
   misclassifications.

4. SINGLE-LEAF FOCUS:
   The pipeline assumes an image contains one prominent, centered apple leaf. It does not perform
   multi-object bounding-box localization.
